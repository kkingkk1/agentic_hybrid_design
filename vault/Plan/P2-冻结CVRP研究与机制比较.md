# P2-冻结CVRP研究与机制比较

所属主计划：[多智能体协作的通用混合算法自动设计](多智能体协作的通用混合算法自动设计.md)。
本文件维护P2的详细比较与验收；阶段状态由主计划第四节维护。

## 目标与进入条件

P1达到预先确定的开发要求，实例清单、预算、独立重复数与统计方案冻结后，开展CVRP求解性能和自动设计机制比较。求解性能同时对照已有混合算法和正式比较前的最新最先进方法。
五角色、候选表示、演化、错误及恢复规则见[P1阶段计划](P1-五角色与开发调试.md)；问题边界、资源映射和混合关系描述见主计划。
受控组按本阶段明确声明的变更和限制执行，其余共用条件遵循P1；不要求受控组执行与其限制冲突的常规修改覆盖、混合关系探索或已禁用功能。
本阶段不以工程通过替代性能或机制结论，也不将待验证的创新性或性能收益写成既成结果。

## 任务与验收

### ☐ 任务1：冻结实例、基线与比较合同

**动作：** 按主计划的CVRP问题定义读取并核验P1交接时冻结的实例清单、预算、独立重复数和统计方案；采用RoCo实例规格及Vidal的HGS基线（[论文](https://arxiv.org/abs/2012.10384)、[代码](https://github.com/vidalt/HGS-CVRP)），核实最新最先进CVRP方法并冻结对照名单、数据用途、版本及选择等其余比较规则。

**交付物：** 本批问题与运行合同、实例来源和文件清单、数据拆分、求解种子、对照方法清单及其来源、核查日期、版本与封装记录。

**验收：** 工程实例、开发集、选版验证和正式测试按用途分开；性能调试只使用工程实例与开发集。对照须包含已有混合算法和至少一种可在同一求解合同下运行的近期最先进方法。正式比较所需的实例清单、模型与角色参数、提示词、预算、对照方法、选择规则、重复数和统计方案未冻结时不启动。

CVRP采用单仓库、同质容量、不拆分需求、最小化总距离，不额外加入时间窗或固定车数。按RoCo预印本v2及其引用的[ReEvo公开生成器](https://github.com/ai4co/reevo/blob/e7d4ba97cccf4677e4a4292f0be805cccc909cbd/problems/cvrp_aco/gen_inst.py)准备数据：仓库位于单位正方形中心，客户坐标在单位正方形内均匀采样，客户需求为1至9的整数，车辆容量为50；规模以客户数计，仓库另计。候选和基线均使用未取整的欧氏距离，独立核对容量、服务唯一性及完整路线。

HGS按[P1阶段计划](P1-五角色与开发调试.md)的要求核对距离计算与车辆上限；正式运行前复核所选版本、实例转换及约束。宿主仍按墙钟统一计时，并独立验解与重算目标；无法满足同合同条件时，不将HGS结果作为同合同对照。
基线记录固定版本、参数及封装差异，并在本机按相同求解合同重跑。公开最优值或BKS保存来源及日期；BKS不称为已证明最优，也不代替同资源算法对照。

正式比较前，根据同一问题定义和可比基准上的公开结果筛选近期最先进方法，不以发表时间单独判定先进性，也不限定其必须为混合算法。记录来源、核查日期、实例、指标、运行资源、可获得实现与选择理由；确认可按本批合同复现后冻结版本。若HGS经核实同时满足最新最先进方法的选择条件，可兼作该类对照，但须记录依据。

正式主结果使用[RoCo预印本v2表7](https://arxiv.org/html/2512.03762v2)所列的CVRP合成测试规格：50、100、200和500客户规模，每个规模按64个实例准备。论文主结果表报告50、100、200规模；500规模列于附录数据表，不能虚构其论文结果。训练、选版验证与测试实例分开；选版验证集是本项目额外设置，须与训练和测试数据互不重合。实例清单、预算、独立重复数与统计方案在进入P2前依据开发材料确定并冻结；拆分、基线版本、具体种子、实用改善阈值及确认批次在正式比较前确定，不预先编造。

上述ReEvo公开生成器的默认验证与测试循环只列出20、50和100客户，不能直接生成RoCo表7中的200和500规模。若扩展该生成规则，须记录实际实现版本、种子、生成顺序和文件校验值；未核实逐实例身份时，不称为RoCo作者原始文件。

通过可承受的小实例穷举、独立枚举或手算核验目标和约束，另测漏服务、重复服务、超容量、非法数值及伪造目标，不依赖Gurobi。评价器未通过时先修正并重验，不使用其结果比较候选。

### ☐ 任务2：冻结候选并完成强基线与最新方法比较

**动作：** 结束设计搜索后锁定候选，按封闭验证规则一次性选版，冻结程序并与HGS及选定的最新最先进方法执行同合同比较。

**交付物：** 冻结源码、依赖、运行配置和构建产物，以及候选、基线的逐实例结果、可靠性和离线设计成本。

**验收：** 相同问题、实例、硬件、核数、计时范围和求解时限下，主要比较冻结程序与对照的解质量；记录实际求解时间并检查是否满足时限。全部组件共用同一截止时间，核型与物理核映射按主计划执行。离线设计投入可不同，但须单列成本；对照方法有预训练时记录其成本和资源。未超过预选的已有混合算法时报告该性能目标未达成，并如实报告与最新最先进方法的差距。

无法在同一合同下复现的最新方法，记录来源与原因，其文献结果单列为背景，不能代替同资源实测。若无法完成最新最先进方法的同合同对照，报告该项未完成，不据此声称已超越该方法。

搜索结束后不得根据封闭验证反馈修复或追加备选；仅经确认满足混合合同且通过规定评价的候选进入封闭验证与最终选版。全部候选经确认失败则报告设计失败；没有合格混合候选时不以单一机制代替交付，证据不足时报告核验未完成。测试只评价冻结程序，不反馈设计、不更新记忆，也不重新选版。已有同合同评价的混合候选按实际评价阶段及证据适用范围报告；证据不足时不判断混合求解器是否具有竞争力。

### ☐ 任务3：比较自动设计系统与联合修改

**动作：** 以完整系统、简单生成及角色合并对照评价系统设计，并从共同有效根候选比较组件与组合修改范围。

**交付物：** G0/G1/G2和J/C/H各组的冻结配置、调用与候选记录、客观评价及实际消耗。

**验收：** 各组采用相同底座、问题合同、混合设计合同及核验规则、评价条件与可见证据时点；匹配允许的主要输入加输出token预算和评价资源上限。各组无合格混合候选时分别记录失败或核验未完成，不用单一机制补齐。所有实际调用、修复和失败计入消耗，不要求各组完成相同调用数或候选数。

| 比较 | 回答的问题 |
| ---- | ---------- |
| G2 vs G0 | 完整自动设计流程相对直接生成与筛选是否有收益 |
| G2 vs G1 | 显式角色、职责交接与上下文组织是否有收益 |
| J vs C/H | 同时开放组件与组合修改是否有益 |

- **G0：** 同等可用知识下直接生成完整程序，由程序评价并筛选符合混合设计合同的候选；可修复执行错误，不利用质量反馈演化方案。
- **G1：** 合并角色身份，保留分析、检索、设计、实现、反思、长期经验、融合和候选维护功能，允许多个顺序调用。
- **G2：** 完整五角色、种群、反思、长期经验，以及单亲修改与双亲重组。

G0、G1、G2是自动设计系统比较组，数字仅区分组别，不预设优劣。P0的最简生成与评价链路仅用于工程验证，允许单一机制，不等同于G0。J/C/H用于独立的组件与组合修改范围比较。

G1与G2保持相同底座、合同、证据及可见时点、预算和评价条件；可比功能阶段沿用对应角色参数。改变项是角色身份、交接和上下文组织，不把取消其他模块混入比较。

J/C/H从相同的合格混合根候选分叉并获得相同新增设计预算：J可改组件与组合；C固定接口及组合，仅改组件内部；H固定组件代码，仅改组合。三组正式候选均须满足同一混合设计合同；算法变化均由设计者先修订思路，再由实现者编码。共同根的成本与失败单列，不免费更换失败根；修改范围通过代码和接口检查，违规记为协议失败。

J优于C/H支持同时开放两类修改有益；只有进一步主张正交互时，才增加父版本、单独组件补丁、单独组合补丁及联合补丁对照，并报告兼容失败。

### ☐ 任务4：按研究主张安排消融

**动作：** 根据实际论文主张选择下列直接对照，不预设全因子或每项独立确认阶段。

**交付物：** 所选消融的冻结配置、独立运行记录、失败与实耗。

**验收：** 每项消融能支持拟讨论的机制，其他条件按任务3保持一致；没有实际融合机会或独立证据不足时限制对应结论。

| 消融 | 唯一改变项或直接对照 |
| ---- | ------------------ |
| 去显式问题分析 | 不执行初始化的问题分析者调用，其余角色可进行必要推理 |
| 去外部检索 | 不查询或注入静态库，保留模型已有知识 |
| 反思分层 | 原始评价反馈、仅短期反思、短期加长期经验 |
| 合并设计与实现 | 合并两项身份，保留其他角色及思路、代码和记录 |
| 关闭融合 | 原双亲重组操作由单亲修改替代，其余流程一致 |
| 种群数量 | 两组都关闭融合，比较多候选与单候选 |

原始反馈组保留真实评价、错误修复和基于质量反馈的改进，但不调用显式Critic或读写反思经验，与G0分开解释。各组从初始化独立运行，正式候选遵循相同混合设计合同和核验规则；被禁用功能在后续迭代及中断续跑中持续禁用。记录实际调用、候选、失败和剩余预算；只有配置与比较条件一致时才复用已有结果。

冻结求解器的组成方法、简单组合或固定调度对照，仅在解释具体混合收益时安排；这类求解算法对照可使用单一机制，不作为系统正式候选或交付。不能删除必要组件使程序失效来制造收益，所有对照共用相同总求解预算。不能借其他角色重新生成被禁用的独立模块产物；其他角色仍可进行完成保留职责所需的推理。

### ☐ 任务5：分析证据并交付结果

**动作：** 按冻结统计方案分析性能、设计机制及失败，分别报告结论强度与适用范围。

**交付物：** 冻结程序、同合同对照结果、与主张对应的机制证据，以及引用原始记录的结果报告。

**验收：** 自动设计机制比较以独立设计运行为主要独立样本，同一程序的求解种子不能充当新的设计样本。报告逐实例配对结果、设计失败、交付成功率、质量差和不确定性；证据不足时限制结论。

指定问题的未见实例、规模或分布变化、新问题重新设计与跨问题迁移分别解释。首版不默认共享跨问题经验，也不因TSP与CVRP都成功就主张覆盖全部组合优化。

## 完成条件与停止处理

完成本批冻结合同要求的已有混合算法、最新最先进方法、系统比较及与实际主张对应的消融，分别报告性能与机制证据、失败和不确定性；最新方法的同合同对照未完成时，P2该项验收不通过。未验证机制不写成贡献。请求响应、源码版本、stdout、评价、实耗及验收记录保存在[outputs/](../../outputs/)，报告引用原始记录，反思摘要不能替代原始证据。
