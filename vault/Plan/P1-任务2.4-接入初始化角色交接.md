# P1-任务2.4-接入初始化角色交接

任务 2.4 的状态由[P1 阶段计划](P1-五角色与开发调试.md)维护。本计划供接入和验收初始化角色交接使用。

## 目标与进入条件

接通问题分析者 → Retriever → 混合方案设计者 → 算法实现者。交付可独立调用的三个角色入口、初始化串联入口，以及待评价的完整设计稿、Python 求解器源码和关联记录。

☑ 任务 2.2 和 2.3 已通过受控验收。复用[正式首版快照](../Knowledge/P1-只读知识库校准/入库口径与校准说明.md#正式首版) `p1-v1-20261118-01`、[初选](../../scripts/p1_retriever.py)和[全文检索](../../scripts/p1_full_retrieval.py)入口。使用[任务 2.2 的 CVRP 样例](P1-任务2.2-接入Retriever初选.md)和[主计划的原问题合同](多智能体协作的通用混合算法自动设计.md)构造受控输入。

本任务用假模型和受控引文支撑判定回调。检索预算复用任务 2.3 的 `check_budget`，用假回调返回允许、拒绝或无法核验，按实际调用次数核对是否发送请求。初始评价和实验经验允许为空。P1 任务 2.5 接收评价事件并接入 Critic，任务 2.6 接入内部记忆，任务 3 承接正式求解接口、独立评价、统一预算账本和续跑。

## 公共交接与记录

- 原问题合同由调用方保留，随分析、设计与实现交接提供。模型生成的表述不得改变原目标或可行域。设计和实现共用一份受控求解接口，明确实例输入、随机种子、时限和完整解格式。
- 每个入口接收可注入的模型调用器和记录回调。固定英文指令与运行数据分别维护，记录组装后实际发送的请求。角色共用模型底座和版本，采样参数可按角色设置。核对调用器实际使用的配置与记录一致。
- 按初始化轮次、角色和尝试顺序关联输入、请求、响应原文或异常、配置、解析和校验结果。检索另关联快照和文件版本，回交另关联缺口、旧设计、新设计及变更说明。记录保存当次值，后续修改不得覆盖旧记录。
- 区分成功、可定位的方案缺口、调用失败和格式失败。缺口可按受控配置有限回交，达到上限时记录原因并停止。调用或格式失败保留原始记录，阻断相应交接。停止时返回原因和可回读的记录，待评价交付只在成功时生成。受控验收的上限仅用于本任务。

## 任务与验收

### ☑ 任务 2.4.1：接入问题分析者

**动作** 实现问题分析者智能体。从原问题合同和设计实例或已知实例格式提炼耦合、分解、表示及可能的混合位置。CVRP 可探索路线解码和基于解种群的搜索。指令要求把已知事实与待验证假设分开，并报告原输入中缺失或冲突的关键事实。

调用方持有原问题合同。模型响应须保留原目标和全部硬约束。按受控合同固定的字段表示逐项核对模型返回的内容，缺失或不一致时报告差异并拒绝交接。通过后从原合同取目标和硬约束组装交接对象。

**交付** 固定英文提示词、可独立调用的分析入口、响应解析与校验，以及交给 Retriever 的 `problem_analysis` 对象。沿用样例的 `problem`、`problem_structure`、`objective`、`constraints` 和 `design_needs`，用可为空的 `hypotheses` 数组保存假设。检索初选和全文请求使用同一份已接受的分析内容。

**验收** 用假模型返回合法分析，捕获现有初选入口收到的对象。验证无效 JSON、缺字段、类型错误和调用异常时没有发起初选。用原问题合同检查受控反例，拦截遗漏容量条件、擅加固定车辆数和把未取整欧氏距离改为取整距离的分析。核对假设在请求中仍标为待验证。受控检查只用于验证这些已知语义边界。

[分析者实现](../../scripts/p1_problem_analyzer.py)提供 `analyze_problem()`。传入原问题合同及 `design_instance` 或 `instance_format`，调用器接收实际请求和 `model_config`。响应声明 `problem_gaps` 或解析、合同校验、调用失败时，记录原因并抛出 `ProblemAnalysisError`。

[受控验收测试](../../tests/test_p1_problem_analyzer.py)已通过。测试使用固定响应和正式快照，由测试代码依次调用分析者、Retriever 初选和全文入口，核对两个实际检索请求收到同一份已接受的分析。正式串联入口由任务 2.4.4 实现，真实模型分析质量留待后续试跑。

### ☑ 任务 2.4.2：接入混合方案设计者

**动作** 实现混合方案设计者智能体。使用原问题合同、分析产物、受控求解接口和检索交接材料设计组件及组合。评价、组件与组合经验在已有时可作为补充输入。固定样例可代替前序角色产物，供本步骤独立验收。

检索交接保留初选理由和最终全文结果，包含适用条件、混合建议所在的 `findings`，以及 `gaps`、快照与文件版本。引用保留条目、字段、逐字引文及行号。设计依赖具体代码或接口时，交接本轮实际发送给全文检索的对应材料。初选理由只作相关性判断。设计和记录应保留 `source`（来源记载）、`paraphrase`（转述）、`inference`（迁移推断）及 `unverified`（待核实）的区别。关键前提仍待核实时，改用无需该前提的方案或报告阻塞。

**交付** 固定英文提示词、可独立调用的设计入口、响应解析与校验，以及可供实现者编码的完整设计稿。设计稿写明组件的用途、复用或改造内容、新设机制、算子和参数策略。明确表示转换、组件接口、适用条件及组合步骤，说明数据和状态如何传递。给出目标计算、硬约束处理、局部子问题边界、共享时限和求解器提前退出时的完整解返回规则。将影响正确性的前提和仅待评价的效果假设分开说明。

**验收** 用含四种证据类别和缺口的样例，核对实际请求包含相关实收材料和各项来源信息。在没有评价和经验时仍能交付完整设计。缺少必要接口、硬约束处理或退出规则的输出在交接前被拒绝。用一项待核实的能力作为受控反例，检查结果保留其不确定性，并避开对该能力的依赖或报告阻塞。

[设计者实现](../../scripts/p1_hybrid_designer.py)提供 `design_hybrid()`。传入原问题合同、分析结果、受控求解接口、初选与全文结果。设计依赖库代码或接口时，用 `full_request` 提供最终实发的全文请求，程序核对问题分析、实收条目和文件版本。设计稿中的证据索引解析为原始结论及引文。待核实结论只能作为假设，迁移推断可条件性参考。响应声明关键缺口时抛出 `HybridDesignBlocked`，格式或合同不合格时抛出 `HybridDesignError`。

[受控验收测试](../../tests/test_p1_hybrid_designer.py)已通过。测试用固定响应覆盖完整设计、缺口和不合格输出，并用正式快照和现有 Retriever 入口产生的交接数据核对兼容性。真实模型的设计质量和求解效果留待后续试跑与评价。

```powershell
python -B -m pytest -q -p no:cacheprovider tests/test_p1_hybrid_designer.py
```

### ☑ 任务 2.4.3：接入算法实现者

**动作** 实现算法实现者智能体。用已接受的设计版本、原问题合同、同一受控求解接口及必要材料生成代码。已有编码和调试经验可作为补充输入。实现者可调整编码细节和改进执行效率，保持算法含义、接口约定及约束处理。关键接口歧义、方案矛盾或需要改变算法的情形交设计者决定。

**交付** 固定英文提示词、可独立调用的实现入口、响应解析与校验。成功时返回完整 Python 求解器源码和实现对应说明，关联依据的设计版本。方案缺口分支返回设计版本、问题位置、冲突依据、影响及需要设计者明确的事项。受控输出中的源码只做语法和入口静态检查。

**验收** 分别用完整设计、含缺口的设计及固定修订稿核对源码提取、静态检查和版本绑定。检查缺口带有可定位依据，实现在修订后使用新稿。保留旧输入输出，交付标为待评价。

[实现者代码](../../scripts/p1_algorithm_implementer.py)提供 `implement_algorithm()`。传入已接受设计稿、`design_version`、原问题合同、同一受控求解接口及设计所需材料。成功返回 `pending_evaluation`、源码、实现对应说明和设计版本。方案缺口返回 `design_gap`、版本、字段路径、可核对的设计引文、冲突依据、影响和所需决定。

本任务的受控 Python 入口为 `solve(instance, seed, time_limit)`，时限单位和输出格式沿用受控求解接口。源码在内存中通过语法编译和 AST 入口检查。真实构建、执行与评价留给任务 3。

### ☑ 任务 2.4.4：串联与方案缺口回交验收

**前置任务** 任务 2.4.1、任务 2.4.2、任务 2.4.3

**动作** 实现初始化串联入口，接通三个角色与现有 Retriever。

**交付** 可复用的初始化串联入口、受控样例和验收记录。成功时返回待评价的设计稿、源码和关联记录，停止时返回原因和已有记录。

**验收** 使用可捕获实际请求的假模型和受控回调，核对以下路径。

1. **正常交付。** 核对调用顺序、同一分析内容和快照、配置与实际请求、全文预检与实发请求的一致性。补读时只交接最终全文结果及对应实收材料。用有非阻塞缺口的 `ok` 结果检查不确定性仍保留。补读因预算跳过时保留此前已核验结论和缺口，后续调用须满足适用的预算前提。核对实现者收到已接受的设计版本，最终交付设计、源码及可回读记录。
2. **检索停止。** 首版遇到 `stopped` 或检索异常时结束当前初始化分支，记录实际原因。验收覆盖未选中材料、证据不足、预算被拒或无法核验，以及快照或配置不一致等异常。检查设计者、实现者均未被调用。
3. **缺口回交。** 用字段齐全但有跨组件冲突的设计通过结构检查，例如解码器可输出超容量路线，而下一组件要求输入始终容量可行。用受控实现者返回定位明确的缺口，由设计者提供完整修订稿及变更说明，再交实现者按新版本生成源码。检查旧稿、缺口、新稿和新源码可关联回读，并验证修订无效或达到回交上限时返回停止原因，不向下游交付待评价源码。该受控样例使用已有检索材料完成修订。

[初始化实现](../../scripts/p1_initialization.py)提供 `run_initialization()`。调用方提供轮次标识、四个角色的模型配置、调用器、预算与支撑判定回调及 `max_revisions`。模型调用器接收阶段、实发请求和所用配置。全文预检沿用 Retriever 的回调，其他请求由串联入口预检。设计版本在同一轮次内从 `design-1` 起编号。修订输入关联旧稿与已定位的缺口，修订输出须有完整新稿和变更说明。成功返回 `pending_evaluation` 及设计、源码、检索材料和记录，停止返回 `stopped`、阶段、原因及已有记录。

[受控验收测试](../../tests/test_p1_initialization.py)已通过。测试复用正式快照和假模型，核对实发请求、版本关联、修订及停止条件。串联和回归验收的本机 JUnit 记录保存在 `outputs/p1_task2_4_4_validation.xml`。
