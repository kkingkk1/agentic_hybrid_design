# CASE-001：HGS-CVRP 的交叉、解码与局部搜索

**摘要：** 对 CVRP 的客户排列进行交叉，经 Split 划分路线后开展局部搜索，再按质量、多样性及可行性维护种群。

**问题结构：** 单仓库、有容量限制的车辆路线问题；每个客户访问一次，各路线从仓库出发并返回，目标为总路线距离最小。源文还讨论车辆上限；具体运行时应核对所用实现的车辆数和距离设置。

**组件分工与连接：**

1. 父代选择使用解质量与种群多样性，选出两个已有路线方案。
2. 顺序交叉使用父代不含仓库分隔符的客户排列，输出新的客户排列。该排列交给 [Split](../算法条目/ALG-001.md)，恢复路线分隔并形成后代路线方案。
3. 对后代运行路线局部搜索，包含 [SWAP*](../算法条目/ALG-002.md) 和其他邻域。若局部搜索后仍不可行，原文以一定概率提高罚系数再执行修复搜索。
4. 后代按是否可行加入相应子种群；子种群达到规模阈值时，按克隆和质量、多样性执行生存选择。搜索期间根据观察到的可行比例调整罚系数；达到无改进次数或时间等停止条件后返回最好可行解。

**信息交换：** 父代向交叉提供客户顺序；交叉向 Split 传递排列；Split 向局部搜索传递分段路线；局部搜索向种群管理传递路线及可行性；可行比例反馈到容量违规罚系数。

**适用条件与限制：** 可行与不可行解在搜索中分别管理，不代表允许最终输出违反原问题约束的解。该案例依赖路线表示、交叉和 Split 的接口相容；迁移至不同约束的问题时须重新核查解码、局部移动与罚函数。文献中的实验结果不等于本项目已经复现或优于任何基线。

**同源独立价值：** 此案例记录完整组合及反馈；ALG-001 与 ALG-002 分别解释解码和邻域算子的独立职责。三条不是三个互不相关的论文，也不是三份不同的代码实现。

**出处：** Thibaut Vidal, 《Hybrid Genetic Search for the CVRP: Open-Source Implementation and SWAP* Neighborhood》，2022；[作者稿 arXiv:2012.10384v2](https://arxiv.org/html/2012.10384v2)，第 2 节、算法 1，第 3—4 节；[正式发表 DOI](https://doi.org/10.1016/j.cor.2021.105643)。2026-11-07 核对正文；未复制或运行源码。
