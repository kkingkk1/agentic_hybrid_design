# ALG-006: Order crossover (OX) for permutations

See [ALG-006.json](ALG-006.json) for the algorithm description and summary. The JSON, code, and source record on this page together constitute one entry.

**Reference code:** [order_crossover.py](order_crossover.py) is an independently implemented project permutation-recombination component using the Python 3.13 standard library. `order_crossover(parent1, parent2, start, end)` returns one offspring without modifying its parents; cut points define a circular interval inclusive of both ends. It does not perform Split or other feasibility checks.

For example, with parents `[1, 2, 3, 4, 5, 6, 7, 8]` and `[4, 5, 2, 1, 8, 7, 6, 3]`, and cut points `2, 4`, the offspring is `[1, 8, 3, 4, 5, 7, 6, 2]`.

**Difference from the case:** In [CASE-001](../../cases/CASE-001/CASE-001.md), HGS-CVRP v1.0.0 `Genetic::crossoverOX` randomly chooses two distinct cut points. When the end is the circular predecessor of the start, the author code's loop copies no first-parent segment and the offspring equals the second parent. This implementation treats that interval as a complete cycle and retains the first parent. It also permits equal cut points for a one-element segment. Both require subsequent route decoding and must not be treated as the same code.

**Validation scope:** On 2026-11-12, [check_order_crossover.py](check_order_crossover.py) checked hand-calculated examples, wrapping segments, invalid input, and 300 random permutations. An independent reconstruction of the author code was compared at each cut: 19,290 non-full-cycle cases agreed. The 5,038 full-cycle cut combinations followed the respective parent-retention rules above, yielding different results for different parents. The authors' complete HGS was not run and no performance benchmark was performed.
