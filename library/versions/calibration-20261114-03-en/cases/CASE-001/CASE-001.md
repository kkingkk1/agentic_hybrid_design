# CASE-001: Crossover, decoding, and local search in HGS-CVRP

**Case file:** [CASE-001.json](CASE-001.json) uses the four-field template; its `description` follows the code's behavior. This page retains the paper evidence, version differences, and boundaries of use. Together they constitute one calibration case.

**Summary:** Cross CVRP customer permutations, decode them with Split, and insert the locally searched offspring into the population; infeasible offspring may be repaired further. Search permits excess capacity and aims to return the best feasible solution found.

**Scope and problem structure:** This entry records the core HGS-CVRP search and population feedback. The source problem is a single-depot vehicle-routing problem with capacity and vehicle-count limits. Every customer is visited once; each route starts and ends at the depot; total route distance is minimized. Search may penalize over-capacity routes. Vehicle-count and distance settings must be checked for the implementation used.

**Components and connections:**

1. Generate $4\mu$ random solutions at initialization, locally search them, and insert them into subpopulations by feasibility. Parent selection chooses two existing individuals using solution quality and diversity.
2. [Order crossover](../../algorithms/ALG-006/ALG-006.json) uses parent customer permutations without depot separators to produce a new permutation. This is passed to [Split](../../algorithms/ALG-001/ALG-001.json), which restores route separators and forms an offspring route solution.
3. Apply route local search to the offspring, including [SWAP*](../../algorithms/ALG-002/ALG-002.json) and other neighborhoods. After ordinary local search, insert the offspring into the appropriate subpopulation by feasibility.
4. If offspring is infeasible, the paper increases penalties tenfold with 50% probability and reruns local search for repair. Its algorithm 1 then reinserts the repaired result; the additional condition in the author code is recorded below. These probabilities and multipliers are source settings, not general defaults for this project.
5. Select survivors using subpopulation size, clones, quality, and diversity. Periodically adjust penalties from the proportion of locally searched solutions that are feasible. In the paper's section 4 CPU-time mode, restart after the non-improvement threshold until the time limit; stopping in other modes must be described separately.

**Information exchange:** Individuals store both customer permutations and routes with separators. Parents pass permutations to crossover; crossover passes a new permutation to Split; Split passes segmented routes to local search; ordinary local search passes routes and feasibility to population management; the fraction of feasible local-search results feeds back to capacity-violation penalties.

**Relation to the algorithm implementation:** The case's `Split::generalSplit` receives the new permutation and the first parent's route count, then sets the decoding vehicle limit to the larger of that count and the ceiling of total demand divided by capacity. It first attempts ordinary Split, falling back to the limited-fleet version if segmentation cannot be recovered under that limit; excess capacity is penalized. The case manifest references the single stored copy of the author Split and dependencies in [ALG-001](../../algorithms/ALG-001/ALG-001.json). The reader assembles these with case-specific files; transfer must still satisfy HGS data structures and parameter requirements.

**Difference between paper and code:** The [public HGS-CVRP v1.0.0 author code](https://github.com/vidalt/HGS-CVRP/blob/35b32d8e9552074f52444d51ea1fe8aec9055467/Program/Genetic.cpp#L11-L18) also inserts offspring after ordinary local search, but reinserts the repair result only if it is feasible. Paper algorithm 1 does not state this additional condition; references must distinguish the pseudocode from this code version.

**Applicability and limits:** Managing feasible and infeasible solutions separately during search does not authorize a final solution violating the original constraints. The paper returns the best feasible solution; if none is found, the return convention of the implementation used requires separate checking. The case relies on compatible route representation, crossover, and Split interfaces. When transferring to other constraints, recheck decoding, local moves, and penalties. Published experimental results do not mean this project reproduced them or outperformed any baseline.
