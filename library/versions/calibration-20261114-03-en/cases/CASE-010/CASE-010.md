# CASE-010: Ant colony and route local search for VRPTW

**Case file:** [CASE-010.json](CASE-010.json) uses the four-field template; its code is assembled from a file manifest.

**Problem and flow:** Ants construct routes using pheromone and distance and may randomly choose a node with a configured probability. During construction, the implementation filters candidates using its time, capacity, and return-to-depot conditions, then separately checks customer coverage. Each iteration selects the best ant. If local search is enabled, it attempts to eliminate one route by relocate and then performs 2-opt. Local search is enabled by default; an improved result is adopted only if the implementation's capacity and time-window checks pass and its score is better. After pheromone evaporation, all ants and the iteration best contribute deposits. Scoring compares vehicle count first and penalized distance second.

**Limits and transfer:** If remaining customers cannot be visited from the depot under the implementation's checks, construction raises an exception. Construction and route evaluation both start at time 0 and omit depot opening time and service time at departure; independently verify timing when the target problem requires them. The Solomon parser discards the input vehicle-count field, and the evaluator does not check a vehicle limit; independently verify fleet limits when applicable. The route evaluator aggregates capacity and time-window violations only under its own time assumptions; a separate function checks exact customer coverage. Recheck coverage after modifying local search. The command line requires a separately supplied Solomon-format instance; plotting depends on matplotlib.

**Validation scope:** On 2026-11-12, the standard-library solver core was run on a synthetic 5-customer instance with a fixed seed; exact customer coverage, loads, time windows, and route distances were independently checked. The complete command line and benchmark instances were not run. On 2026-11-12, small in-memory examples reproduced both a route violating time windows being judged feasible when depot opening time is nonzero, and the program returning 2 routes as feasible when the input vehicle count is 1.
