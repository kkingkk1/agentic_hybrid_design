# CASE-003：TSP 的迭代局部搜索

**案例文件：** [CASE-003.json](CASE-003.json) 使用四字段模板，代码由文件清单组装。

**问题与流程：** 对二维欧氏对称 TSP 使用客户排列和取整距离。入口先用最近邻构造初始回路，再复制当前最好回路做 double-bridge 扰动，依次使用 2-opt、Or-opt 和 3-opt 局部搜索，并在候选更好时更新最好解。循环按时间限制停止。

**限制与迁移：** 扰动重排 tour 后未同步 pos，局部搜索却用 pos 寻找前驱、后继和移动位置。已用 10 节点输入复现位置不一致，移动评价和所得结果因此不能直接信任。复用前应同步索引并独立检查排列和路长。扰动代码要求足够多的节点；原程序还无条件导入 networkx 与 matplotlib，即使未启用画图。

**验证范围：** 2026-11-12 将缺失的 networkx 绘图导入替换为内存占位，在 10 节点合成输入上运行最近邻、局部搜索和短时迭代，检查了排列、路长和不劣于初始局部解；另用同类输入复现上述位置索引问题。该检查不代表原环境依赖齐全，也不证明实现普遍正确。

**来源与使用条件：** 源码来自 [shunji-umetani/tsp-solver 固定提交](https://github.com/shunji-umetani/tsp-solver/tree/1122bd112e6cd62f5733c2a722b96b78af015c07)，提交为 `1122bd112e6cd62f5733c2a722b96b78af015c07`。入口为 [tsp_ils.py](tsp_ils.py)；本案例保存 2 个来源文件，包括原始 LICENSE，未修改来源文件。仓库采用 MIT 许可，保留原始版权与许可声明。JSON 文件清单锁定每个来源文件的 LF 归一化 SHA-256；初次入库时每个文件还与上游 Git blob 哈希核对。依赖清单只记录源程序需要的环境，不代表本项目已安装这些依赖。
