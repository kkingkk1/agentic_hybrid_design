# CASE-004：TSP 的规模分支与局部改进

**案例文件：** [CASE-004.json](CASE-004.json) 使用四字段模板，代码由文件清单组装。

**问题与流程：** 程序读取坐标并构造取整欧氏距离矩阵，尝试多个起点的贪心路线。自动模式按节点数选择后续流程：不超过 50 个节点用模拟退火；51 至 500 个节点先拆除交叉路径，再做 2-opt；更大实例直接做 2-opt。命令行可覆盖该选择，结果写入指定文件。

**限制与迁移：** 模拟退火分支用 range(int(time / 30 - 1)) 决定运行次数；非负时间小于 60 秒时循环不执行，最终路线和代价为 None。输入路径和依赖须由调用方提供，返回的闭合路线重复起点。时间参数并非所有分支共享的严格中断保证。

**验证范围：** 2026-11-12 在已安装的 Python 环境中，以 5 节点合成距离矩阵分别调用贪心构造和 2-opt，独立检查闭合回路、节点覆盖、距离与改进关系。未运行默认模拟退火分支或完整命令行。

**来源与使用条件：** 源码来自 [LaurenceLungo/TSP-Solver 固定提交](https://github.com/LaurenceLungo/TSP-Solver/tree/54ab033c84373238d09665d7d3b0e80c850c6501)，提交为 `54ab033c84373238d09665d7d3b0e80c850c6501`。入口为 [solve_tsp.py](solve_tsp.py)；本案例保存 8 个来源文件，包括原始 LICENSE，未修改来源文件。仓库采用 MIT 许可，保留原始版权与许可声明。JSON 文件清单锁定每个来源文件的 LF 归一化 SHA-256；初次入库时每个文件还与上游 Git blob 哈希核对。依赖清单只记录源程序需要的环境，不代表本项目已安装这些依赖。
