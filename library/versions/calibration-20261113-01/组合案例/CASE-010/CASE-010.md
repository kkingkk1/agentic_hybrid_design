# CASE-010：VRPTW 的蚁群与路线局部搜索

**案例文件：** [CASE-010.json](CASE-010.json) 使用四字段模板，代码由文件清单组装。

**问题与流程：** 蚂蚁按信息素与距离构造路线，并可按设定概率随机选点。构造时按实现中的时间、容量和返回仓库条件筛选候选，结束后单独核对客户覆盖。每轮选出最好蚂蚁；启用局部搜索时，尝试通过 relocate 消除一条路线，再做 2-opt。局部搜索默认启用，只有实现中的容量和时间窗检查通过且评分更好才采用改进结果。信息素蒸发后，所有蚂蚁和当轮最好解均参与沉积。评分优先比较车辆数，再比较含罚项的距离。

**限制与迁移：** 当剩余客户按实现中的检查无法从仓库访问时，构造过程抛出异常。构造与路线评价均从时间 0 开始，不计入仓库开放时间或出发时的服务时间；目标问题要求这些条件时，必须独立验算时序。Solomon 解析器丢弃输入中的车辆数字段，评价器不执行车辆数上限检查；目标问题有车队上限时须独立核验。路线评价器只汇总其时间假设下的容量和时间窗违反量，客户是否恰好覆盖由独立函数检查；修改局部搜索后应重新检查覆盖。命令行需另行提供 Solomon 格式实例；绘图入口依赖 matplotlib。

**验证范围：** 2026-11-12 使用标准库求解核心和固定种子运行 5 客户合成实例，独立核对客户恰好覆盖一次、载重、时间窗及路线距离；没有运行完整命令行或基准实例。2026-11-12 以内存小实例复现：非零仓库开放时间可能导致违反时间窗的路线被判为可行；输入车辆数为 1 时，程序可返回 2 条路线并报告可行。
