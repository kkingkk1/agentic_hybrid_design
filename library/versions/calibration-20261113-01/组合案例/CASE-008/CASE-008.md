# CASE-008：CVRP 的变邻域搜索

**案例文件：** [CASE-008.json](CASE-008.json) 使用四字段模板，代码由文件清单组装。

**问题与流程：** 程序以客户访问顺序表示候选，并在 CVRP 评价中按约束生成路线。示例先用最近邻产生顺序，再比较若干方法，其中 VNS 每轮先随机扰动顺序，再用 swap 或 insertion 做局部搜索。严格改善时记录最好解并回到首个邻域，否则尝试下一个邻域；计时器可提前结束。

**限制与迁移：** 局部搜索未改善时，代码保留扰动后的 current_solution，但 current_solution_value 仍是先前数值；下一轮并非恢复到先前接受解的标准 VNS。示例输入文件不在此案例中。main.py 导入 solver.py 先于创建日志目录，运行前须自行准备预期路径。评价器只核对输入顺序中的位置是否均已处理，不核对客户是否重复或覆盖完整集合；已复现一名客户重复、另一名客户缺失时仍返回有限成本。迁移时须独立检查客户覆盖、路线解码与容量。

**验证范围：** 2026-11-12 核对 VNS、评价器和主程序的实际源码，并在 5 客户合成实例上运行 CVRP 的 VNS，独立核对客户覆盖、容量与路线成本；测试时将日志文件和绘图目录的创建替换为内存占位。另用重复和遗漏客户的输入复现评价器返回有限成本的问题。未运行原始主程序或真实数据；原仓库依赖记录保留在 requirements.txt。
