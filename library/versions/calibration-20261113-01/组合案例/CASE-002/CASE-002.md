# CASE-002：PDPTW 的 ALNS 与 CP-SAT 第三方变体

**案例文件：** [CASE-002.json](CASE-002.json) 使用四字段模板；本页记录代码来源、与论文的区别和已发现的限制。两者共同对应一个校准案例。

**摘要：** 第三方实现将自适应移除、插入和模拟退火用于带时间窗取送货问题，并定期尝试用 CP-SAT 重排单条路线。本案例不是 2006 年 ALNS 论文的作者实现。

**问题与组合：** 每个订单包含取货和送货节点；代码检查路线容量、时间窗、时长、每车订单数和取送顺序，目标计算路线距离与车辆固定成本。初始解按送货时间窗截止时间排序并贪心插入。搜索独立按权重选择移除和修复算子；移除包含随机、相关性、贡献和整路线四种，修复包含贪心、Regret-2 和带噪声插入。修复失败或未通过实现中的可行性检查时丢弃候选；其余候选经模拟退火接受判断，并根据最好解、当前解改进或接受结果给算子计分。每段更新权重并降温。

**精修与停止：** 达到配置的间隔且该轮修复通过检查时，代码尝试逐路线调用 CP-SAT 重排；单条候选路线经其路线检查后返回。只要路线发生变化且计算成本有限，精修结果便替换当前路线，代码没有额外要求总成本严格下降。搜索受迭代数和循环开头检查的墙钟时间限制；一次路线精修可能跨过总时间上限。

**已知实现限制：** 初始构造忽略单个订单插入失败；`all_orders_served` 只统计取货节点集合，不能保证所有取送节点配对且各出现一次；`total_cost` 忽略路线检查失败标记，因而不能保证不可行路线对应无穷成本。2026-11-12 在内存中用小例子复现了缺少送货仍被判可行，以及不可行路线仍得到有限成本两种情况。精修后的有限成本判断不能替代独立可行性验证。此样例仅作组合设计参考，不能据此认定输出可行或实验结果可信；迁移时须重新实现或核验上述检查，并按目标问题处理取送配对、未安排订单和约束。

**代码版本与使用条件：** JSON 的 `code` 以文件清单登记 [or-algo-opt/pdptw-alns-vs-routing 固定提交](https://github.com/or-algo-opt/pdptw-alns-vs-routing/tree/6fd6c8afa5aa652b65187ca6e52e1c1131d22d49)中 `alns_pdptw/` 的全部 11 个 Python 文件、`requirements.txt` 和原始 `LICENSE`。文件保存在本案例目录内，每项锁定内容哈希；读取器校验后按 `# --- FILE: 路径 ---` 组装完整源码。项目将 `data.py` 中未使用且未定义的 `K_NEAREST` 导入，以及 `route_optimizer.py` 中未使用且未定义的 `SOLVER_MERGE_TIME_LIMIT` 导入移除；其余源码保持该提交原样。源码使用 MIT 许可，版权归 or-algo-opt；复制和分发时保留所附版权及许可声明，外部模型的具体服务条件尚未逐项核实。依赖版本见代码中的 `requirements.txt`；OR-Tools 的 CP-SAT 是本案例的外部依赖，不代表本项目整体依赖该工具。2026-11-12 核对源码和许可，未运行完整算法或 CP-SAT。该 JSON 当前 UTF-8 文件的 SHA-256 为 `772b0b3564fe967277ed87a9bf45583ee18d6186ac54a8c0bf250f96ad81b3be`；文件改动后须重新记录对应版本。

**与论文及算法条目的关系：** [ALG-003](../../算法条目/ALG-003/ALG-003.json) 和 [ALG-004](../../算法条目/ALG-004/ALG-004.json) 分别解释 2006 年论文的算子选择与 Regret-k；本案例是相似思路的第三方实现，不声称逐步复现论文。两个算法条目的项目参考代码独立编写，案例未调用这些代码。案例的评分未使用论文所述的解历史新颖性判据，初始及失败请求处理、分段降温、目标和 CP-SAT 精修也不同。原论文一般模型包含 request bank；本案例不能假定有同样机制。

案例的相关移除使用一个种子并直接选取最相关请求，高代价移除在开始时计算并排序一次；[ALG-008](../../算法条目/ALG-008/ALG-008.json) 和 [ALG-009](../../算法条目/ALG-009/ALG-009.json) 则按论文的随机偏向逐次选择，后者还逐次重算收益。[ALG-007](../../算法条目/ALG-007/ALG-007.json) 解释模拟退火接受准则，其参考代码没有案例中的最低温度。这些参考代码同样未被案例调用。

原论文一般模型将行驶距离、车辆工作时间和未安排请求数量计入加权目标，搜索可以经过含未安排请求的状态；论文所述实验要求最终解安排全部请求。论文中的移除和插入算子分别选择，并按分段搜索结果更新权重；具体机制以两个算法条目及论文为准，不应用来替代本案例的代码说明。
