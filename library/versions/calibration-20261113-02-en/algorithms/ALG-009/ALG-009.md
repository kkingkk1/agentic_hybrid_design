# ALG-009: Worst request removal

See [ALG-009.json](ALG-009.json) for the algorithm description and summary. The JSON, code, and source record on this page together constitute one entry.

**Reference code:** [worst_removal.py](worst_removal.py) is a project removal component independently implemented from the paper, using the Python 3.13 standard library. `worst_removal(routes, node_request, count, power, objective, rng)` returns new routes and removed requests. Routes exclude the depot; the mapping must cover exactly the visited nodes and nodes of the same request must be in the same route. The objective callback receives an immutable route snapshot and, following the paper's convention, calculates the objective without counting removed requests in a request bank.

After each removal, the gains of remaining requests are recalculated. Empty routes remain in the result; the objective callback must determine from the problem whether an empty route incurs vehicle cost. The mapping cannot reveal pickup-delivery nodes that were already missing. The caller handles the request bank, repair, and final feasibility. This implementation differs from the third-party code in [CASE-002](../../cases/CASE-002/CASE-002.md). The project reference code has no separately declared open-source license.

**Validation scope:** On 2026-11-12, [check_worst_removal.py](check_worst_removal.py) checked repeated recalculation, randomized ranking, grouped removal, input preservation, and invalid inputs. Another 100 fixed-seed cases were compared against an independent removal procedure. Complete ALNS was not run and no performance benchmark was performed.

**Source:** Stefan Røpke and David Pisinger, *An Adaptive Large Neighborhood Search Heuristic for the Pickup and Delivery Problem with Time Windows*, section 3.1.3 and algorithm 3 of the [2006 published-version MinerU text](../../../../../data/P1_calibration_papers/ALNS_2006_MinerU/full.md); [published DOI](https://doi.org/10.1287/trsc.1050.0135). On 2026-11-12, the parsed text, algorithm 3 on local original PDF page 6 (printed page 460), and the third-party code included in CASE-002 were checked. The paper authors' code was not run.
