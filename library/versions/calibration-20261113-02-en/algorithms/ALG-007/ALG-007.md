# ALG-007: Simulated-annealing acceptance

See [ALG-007.json](ALG-007.json) for the algorithm description and summary. The JSON, code, and source record on this page together constitute one entry.

**Reference code:** [annealing_acceptance.py](annealing_acceptance.py) is an independently implemented project acceptance and cooling component using the Python 3.13 standard library. `annealing_accept(current, candidate, temperature, rng)` evaluates a candidate and draws a random number only when it is worse. `cool_temperature(temperature, rate)` performs one geometric cooling step and raises an exception if the result underflows to zero; the caller decides whether to stop or take other action.

The component sets no initial temperature, minimum temperature, or stopping condition; it does not compute objectives, generate candidates, or check feasibility. Acceptance uses a logarithmic comparison to avoid underflow when directly exponentiating very small probabilities; floating-point logarithm precision still affects decisions near the boundary. Output temperature is converted to float and may overflow for very large values. This implementation differs from the third-party implementation in [CASE-002](../../cases/CASE-002/CASE-002.md), which sets a minimum temperature.

**Validation scope:** On 2026-11-12, [check_annealing_acceptance.py](check_annealing_acceptance.py) checked improvements, equal and worse candidates, extreme values, cooling, and invalid inputs; another check compared 10,000 deterministic random decisions against direct exponential probabilities. Complete search quality was not evaluated. The project reference code has no separately declared open-source license.

**Source:** Stefan Røpke and David Pisinger, *An Adaptive Large Neighborhood Search Heuristic for the Pickup and Delivery Problem with Time Windows*, section 3.5 of the [2006 published-version MinerU text](../../../../../data/P1_calibration_papers/ALNS_2006_MinerU/full.md); [published DOI](https://doi.org/10.1287/trsc.1050.0135). On 2026-11-12, the parsed text, acceptance and cooling formulas on local original PDF page 8 (printed page 462), and the third-party acceptance code included in CASE-002 were checked. The paper authors' code was not run. The paper also gives a problem-specific initial-temperature setting, which this component does not adopt by default.
